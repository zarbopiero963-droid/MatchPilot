## Notes

- **REAL label check (item 9):** the UI has no "REAL" badge at all. `states.js:10-16` defines DEMO, PIT, NON_PIT, NON DISPONIBILE, N/D; `badge('DEMO')` is never used in `app.js`. PIT/NON PIT come from the API field (`pitBadgeKind`, :970-973, :749). No value is labelled REAL or certified without API evidence; the only fixed claims are the "not certified" texts (FE-47).
- **Hard-coded lists that are correctly API-driven (no finding):** competitions (`/fpt/competitions`, `/fpt/coverage-competitions`), countries (derived from coverage rows, :334), seasons (`/fpt/coverage-seasons`), teams (`/fpt/teams`). No country/season/bookmaker list exists in the browser.
- **Duplicated API vocabulary in the browser:** `DEF_FIELDS` (:944), `CMP_DATA`/`CMP_STRATEGY` (:1453-1454), `SIM_FIELDS` (:953), `SEARCH_FIELDS` (:768) copy parameter names that `/api/v1/endpoints` already publishes with text descriptions (`endpointsView`, :911-932). Moving to typed metadata (enum, min, max, unit, default) would resolve FE-09, FE-10, FE-30, FE-31, FE-44 in one change.
- **Backend observation relevant to FE-01/FE-09:** `fpt_match_facts` stores `odd_over25`, `odd_under25`, `odd_btts_yes` and the search API filters on `over25`, while strategy-def.mjs:11-12 states "the archive carries 1X2 prices only". Both cannot be the general rule; MP-PRODUCT-100 needs an explicit capability list per market.
- **Filters accepted by the backend and missing in the GUI:** search `season`, `phase`, `limit`; backtest `outcomes_as_of`; coverage `min_seasons`, `min_matches`, `min_odds_coverage`. **Filters in the GUI with no backend counterpart:** none (every `SEARCH_FIELDS` key is in `SEARCH_FILTERS`, every `SIM_FIELDS` key is in `/hist/backtest`).
- **Match Center:** no live/PREMATCH-vs-LIVE separation exists in the UI (archive-first phase); only FPT historical rows are analysed.
