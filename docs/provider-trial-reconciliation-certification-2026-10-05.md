## Odds semantics

BetsAPI Event Odds is normalized using documented market keys rather than generic labels.

Examples:
- `1_1` — soccer 1X2
- `1_2` — Asian Handicap
- `1_3` — Goal Line / Over-Under
- other sport/market keys remain intact as returned by BetsAPI

For each normalized odds observation the pipeline preserves, where available:

- provider
- sport_id
- country_code
- league_id
- league_name
- event_id
- kickoff_utc
- phase
- bookmaker
- market_key
- selection_key
- line_value
- price
- provider_time
- observed_at
- raw_path

Opening, latest and closing are ordered by provider time / `add_time`, with local observation time used only as fallback.

Closing is never fabricated: it is the last provider-time price at or before kickoff.
